A remote message whose body parses and whose SAID verifies, but which carries a field value that is not valid for its type, is now refused as that one message instead of ending the agent runtime. Before, a non-hex or over-wide sequence number, a junk key, next-key digest or witness, a key state notice whose `d` is not a digest, a reply whose prefix, URL or `dt` does not decode, a v2 query or exchange whose sender is not a prefix, or a nested message on a frame that cannot carry one threw a codec error out of dispatch. One such receipt in a mailbox wedged the poller on every restart; an out-of-order event with junk keys, or an escrowed key state notice with a non-digest, failed every escrow pass.

Each boundary now decides the field values once, before any escrow decision or store write, through the guarded readers in the new `core/wire-fields.ts`: `Kevery.decideEvent` rejects with the new `malformedField` reject code (or `invalidSn`/`invalidPre`), `processReceipt` emits its existing `invalid` cue, the `/ksn`, `/watcher`, `/end/role` and `/loc/scheme` handlers and `Revery`'s `dt` read raise the `ValidationError` that dispatch reports as an `invalidMessage` drop, `Exchanger` admission rejects, and `queryEnvelopeFromDispatch` treats such a sender as unauthenticated. `ProtocolProcessor.dispatch` refuses a frame with unsupported nested messages as an `invalidMessage` drop. Escrow replay re-enters these same checks, so a row stored with a malformed value is removed as rejected. Errors from store reads and other faults still propagate.
