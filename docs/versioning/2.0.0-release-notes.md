# 2.0.0 release notes

Coordinated versions: **cesr-ts, keri-ts, @keri-ts/tufa, @keri-ts/hosting,
@keri-ts/registrar, @keri-ts/wallet, @keri-ts/verifier and @keri-ts/observer
2.0.0**. The five scoped application packages are new on npm. 2.0.0 tracks KERIpy
2.x feature parity and implements the ToIP KERI/ACDC/CESR v1.1 specifications;
see [version numbers](release-versioning.md#version-numbers). No 1.0.0
package, tag or release is replaced. @keri-ts/multisync stays unpublished.

## Breaking changes

- CESR removes ESSR payload sink/ownership and reader adapters; use ordinary bytes.
- KERI separates input Reactor from shared ProtocolProcessor, requires explicit
  HTTP/clock dependencies, removes RuntimeServices and uses concrete messengers.
- Poster queues signed messages for an independent worker. Cue/replay/result
  names and workflow signatures change; transport completion never means approval.
- HTTP returns owned finite bytes or scope-borrowed streams; TCP sends return
  completion. CESR body-mode configuration and local mailbox self-consumption go.
- ESSR evidence belongs to Baser's LMDB Texter set. Filesystem archives, durable
  decrypted plaintext and staging/ownership machinery are removed. Old keri-ts
  private formats have no compatibility reader or migration layer.
- Database close failures propagate and prevent uncertain handle reuse/reopen/delete.
  Final command success follows cleanup; completed mutations survive later close failure.
- KERI command helpers return typed data for Tufa to render. Query waits for real
  accepted recovery; malformed CLI/configuration values fail before storage effects.
- The verifier webhook application moves to `@keri-ts/verifier`; KERI keeps
  protocol Verifier and evidence. Tufa's `runtime`, `host/kernel` and
  `http/protocol-handler` entrypoints are removed; host kernel and protocol
  handler imports move to `@keri-ts/hosting`.
- Verifier graph evaluation uses one upstream-aligned ACDC chaining evaluator;
  the private graph evaluator and its unsupported operator/schema profiles go.
- Local credential applications author NoBackers legacy TELs. Backed-registry
  authoring/rotation is removed; external backed-TEL observer verification remains.
- Credential completion separates acceptance, TEL publication and saved evidence.
  Revocation requires verified issuance authority. Exact-version replay refuses
  incompatible evidence rather than silently raising its output version.

The [migration guide](../reference/compatibility/MIGRATING_TO_2_0.md) compares the
published 1.0.0 package surfaces, names replacements and explains caller actions.
The [source-pinned guide](https://github.com/kentbull/keri-ts/blob/f50fbf89e191f94c9cbe5233dec1b7ca45de62fa/docs/reference/compatibility/MIGRATING_TO_2_0.md)

## Included behavior

Legacy group VCP/ISS/REV and all six IPEX verbs support member approval/fanout,
exact-event resume, business-evidence validation and historical signer election.
Init/incept owns finite OOBI/authentication bootstrap. `tufa oobi clean` previews
and applies exact pending keys through ordinary Baser loading. Secret reencryption
is atomic; transport cleanup, mailbox cursors and escrow diagnostics are corrected.
Packages are organized by cohesive protocol/application/CLI/storage responsibility.
Ajv is pinned to patched 8.18.0; neither schema owner enables `$data`.

ACDC v2 registries and blinded/bound disclosure verify openings against their
declared digests and carried bytes, and commit sections with compact-form
commitments. IPEX gains individual DHKE for approved pending Grants, Unblind
openings with live Unblind as the default, DH/Unblind requery and retained
consent queries. Wallet negotiation, explicit unblinding and exact-view
presentation run through the CLI. Mixed KERIpy/Tufa groups run as explicit v1 or
v2 groups, and group proposals use KERIpy's embedded form. Numeric thresholds
count distinct verified signer indices, so duplicate signatures from one key
cannot supply multiple votes.

New packages: `@keri-ts/hosting` owns the HTTP host kernel, Hono app policy and
protocol routes, plus a hosted-witness backend following upstream witness-hk.
`@keri-ts/registrar` publishes allow-listed signed registry evidence and answers
bulk queries; `@keri-ts/observer` schedules HTTPS source observation with signed
cache-only queries; both run as TLS services with persistent account enrollment.
`@keri-ts/wallet` and `@keri-ts/verifier` own the wallet and credential-verifier
applications. Package changelogs list each change.

## Interoperability boundaries

The default reference is the KERIpy v2-spec candidate `kentbull/keripy`
`2b19fa875d8c803c613087102db51b9e07124588`, together with the pinned ToIP KERI,
ACDC and CESR specification commits and candidate applications in
[`scripts/ci/keripy-reference.json`](../../scripts/ci/keripy-reference.json).
Frozen legacy profiles remain WOT main `c7e74adc3129ba36302db32e58056560b0927424`,
GLEIF-IT 1.2.17 `b8626e1d58770a4a480ea72a01acc5580278a9f2` and WOT 1.3.x
`4ce4cc79e06653f77342be1bf604086b89b1f090`. A package version does not select
KERI/ACDC/CESR versions. Actual CLI evidence and public-API evidence are distinct.

Pinned Python CLI URL/framing/protected-source limitations remain
[documented](../reports/interop/KERIPY_MULTISIG_VCP_GENUS.md), as does main's
[ESSR ordered-set reconstruction limitation](../reports/essr/KERIPY_REPEATED_FRAGMENTS_2026-10-20.md).
The [parity roadmap](../plans/PARITY_ROADMAP.md) records deferred multi-key witness
authentication and the two v2 registry opening-retention divergences from KERIpy.
Delivery acks, durable outboxes, generic retries, generic database providers and
broad Python porting remain future work.

## Qualification

2.0.0 is published before a fresh full qualification battery at its release
commit. The release commit passes the static, manifest, version and changeset
checks and the PR gate; the full source, interop, manual and installed-artifact
battery runs after publication, and any regression it finds ships as a 2.0.x patch.
The [October preparation report](../reports/parity/V2_PREPARATION_2026-10-21.md)
qualified the earlier source `f50fbf89` only; it does not qualify the later v2
ACDC registry, IPEX and service-package work included here.
