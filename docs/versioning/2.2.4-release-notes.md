# 2.2.4 release notes

Published versions: **keri-ts, @keri-ts/hosting, @keri-ts/wallet and @keri-ts/tufa 2.2.4**, and
**@keri-ts/registrar, @keri-ts/verifier and @keri-ts/observer 2.2.2**. cesr-ts stays at 2.2.1. Every
package that depends on keri-ts pins 2.2.4. The package tags and `v2.2.4` are at `494decc0`.

2.2.4 makes an idle runtime cheap (#1035). Nothing here changes a wire format, an event or the result
of any call. The other packages carry no change of their own; they are republished because each pins
keri-ts exactly. Package changelogs list every change.

## Idle runtime cost (#1035)

An idle `runAgentRuntime` used a third of a core. Two delivery workers spun on a zero-delay timer, and
every loop scanned its store rows on every tock whether or not anything could have changed.

- **Fixed tocks, no spins.** The postman and query-sender workers run as fixed-tock doers and look only
  at their in-memory queues. A queued message waits at most one tock before delivery starts.
- **One tock setting.** `protocolPacing.tockMs` now also governs the escrow loop and those workers.
  Doers wait for the next tock boundary, so loops with the same tock wake the host together.
- **Scans need a reason.** The escrow loop, OOBI resolution, authentication, delegation, group
  counseling and TEL publication scan their store rows on tock 0, after this handle wrote the store,
  when they hold work in memory, and every `idleTocks` tocks for work that only time releases.
- **`DoerPacing.idleTocks`**, default 32, sets that last interval.
- **`Dber.writeActivity`** is the write signal: an in-process counter raised by every row write on the
  LMDB store, the memory store and the browser store. A transaction that changes no row does not
  count. The escrow loop reads the counters of the KEL store and the registry stores.
- **Another process.** The counter is in-process. A row written to the same store by another process
  is seen within `idleTocks` tocks, about one second at the default pacing. The browser store has a
  single writer, so the wallet is not affected.

### Measured

Idle CPU on the development host, as a share of one core:

| Runtimes | Before       | After        |
| -------- | ------------ | ------------ |
| 1        | 0.35 to 0.40 | 0.12 to 0.14 |
| 20       | 1.17         | 0.56         |

What remains is the number of loops times their wake rate. Fewer loops or slower default tocks is the
next change and is not in this release.

### Not confirmed

`interop (interop-kram)` failed twice on the branch at the registry-root re-seal after a mixed group
rotation, and passed on the final run. It was not reproduced locally, and which fix resolved it was
not isolated; the likely cause is the write signal counting empty transactions. The test now prints
the rotate command's output when that assertion fails.
