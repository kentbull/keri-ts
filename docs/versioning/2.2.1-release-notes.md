# 2.2.1 release notes

Published versions: **keri-ts, @keri-ts/hosting, @keri-ts/wallet and
@keri-ts/tufa 2.2.1**. **@keri-ts/registrar, @keri-ts/verifier and
@keri-ts/observer 2.2.0**, published for the first time on the 2.2 line.
cesr-ts stays at 2.2.0. The release commit is `49e175e1` (version PR #990), tagged
`v2.2.1`.

Two publications need a word:

- **Tufa.** `@keri-ts/tufa` 2.2.0 never published (see the
  [2.2.0 notes](2.2.0-release-notes.md)), so 2.2.1 is the first Tufa on npm since
  2.1.0. The stale CLI test expectations that stopped its release workflow were fixed
  in #987.
- **Registrar, verifier and observer.** They were not republished with 2.2.0, and their
  2.1.0 tarballs pin keri-ts 2.1.0 exactly, so a keri-ts 2.2 consumer could not use
  them. They are published as 2.2.0 against keri-ts 2.2 with no API change of their
  own (#993). `@keri-ts/hosting` is republished for the same pin reason.

2.2.1 is a patch release: it fixes defects found by the 2.2.0 qualification and adds
no API a 2.2.0 caller must adopt. The one status change a caller may notice is below.
Package changelogs list every change.

## What changed

- **Group DH issuance in a browser wallet.** A member that holds only the
  mailbox-delivered proposal of a fresh group DH issuance can now consent to it with
  `proposals.approve`. Before, the wallet offered the Grant as a plain group IPEX message
  too and took that call first, so consent failed with "ACDC v2 group graph is false or
  unresolved". `groupIpexProposals` no longer lists a fresh issuance Grant, and the two
  lists agree. That error now names each node's verdict and reason.
- **`proposals.approve` returns a refusal instead of throwing** for an IPEX or issuance
  proposal the library will not approve yet: `{ outcome: "refused", reason }`, with
  nothing signed.
- **Recording a group issuance.** A group member that approved the registry update now
  records the issued credential in its inventory (`RegistryCustody.issuedOpening`).
- **Group events no longer wait about 60 s.** A non-elected member fetching witness
  receipts met a reply it could not parse from the pinned KERIpy witness (it counts a v2
  receipt group in items, not quadlets) and waited out the 60 s fallback grace before
  submitting itself. A parse error on the fetch now makes it submit at its next attempt.
  Group inception, registry and rotation steps in the browser lane dropped from about
  62 s to a few seconds.
- **Group wrappers go to each member independently (#994).** Publishing a group proposal
  or approval no longer throws at the first member without a route after the event is
  accepted locally. Each other member has its own `GroupDelivery` outcome (`delivered` or
  `failed` with a reason) in the result's `members`, the Counselor always starts, and a
  caller can send a failed wrapper again. `Poster.canReach` still refuses an inception
  up front. Tufa prints `members`.
- **Waits hold open while a delivery is owed (#989).** `waitForIssuance`,
  `waitForPresentation` and `waitForUnblinding` no longer settle while the live
  operation still holds a message in its outbox (`owes`). A group issuer member's
  `tufa ipex grant --issue --resume` now stays until its DH contribution is handed to the
  transport, so a KERIpy custodian reaches quorum instead of expiring.
- **Tufa.** `tufa multisig join --kind <kind>` approves only a pending proposal of that
  kind and refuses a `--said` of another kind. `tufa ipex` group commands with
  `--acdc-v2` publish the group proposal before the approval wait, so
  `--approval-timeout 0` still proposes. `tufa multisig rotate` and `join` print the
  registry root copies the runtime had already sent for a rotation.

## Known defects in 2.2.1

Found after publication; all are fixed in [2.2.2](2.2.2-release-notes.md).

- In a browser bundle, constructing any keri-ts error threw a `TypeError`, which stopped
  the runtime that raised it. This also affects 2.2.0.
- A browser wallet could not hold a host's signers as it opened, so the first mailbox poll
  of an identifier whose keys the host keeps was unsigned. This also affects 2.2.0.
- Under a strict Content-Security-Policy without `'unsafe-eval'`, schema pinning and
  validation failed. This also affects 2.2.0.
- A released signer (`Manager.release()`) ended a running runtime on the next mailbox poll.
- Several local identifiers advertising one ingress URL answered 409 "Ambiguous hosted
  endpoint path".
- A `/multisig` wrapper addressed to an identifier the receiver does not hold, or sent by
  a non-member, was stored, noticed and listed.
- A group member that only receives never accepted an event the lead completed alone.
- A non-transferable group member could not read its group's mailbox on a keri-ts host.
- One Habery could not be a party on both sides of one Grant (a host with two tenants).

## Qualification

The 2.2.0 qualification run (#985) found the defects fixed here. The full battery was
completed against 2.2.2, not 2.2.1; see the 2.2.2 notes.
