# 2.2.2 release notes

Published versions: **keri-ts, @keri-ts/hosting, @keri-ts/wallet and @keri-ts/tufa
2.2.2**, and **cesr-ts 2.2.1**. @keri-ts/registrar, @keri-ts/verifier and
@keri-ts/observer stay at 2.2.0. The packages are tagged at `381a01d4`: version PR #997
(`5414b6b1`) plus the test-only #1018. cesr-ts is tagged `cesr-v2.2.1` at `5414b6b1`.

2.2.2 is a patch release, but it changes several types and one thrown error. They are
listed first because they can break a caller's compile or its error handling. For the
surfaces that moved in 2.2.0, read the
[migration guide](../reference/compatibility/MIGRATING_FROM_2_1.md); for how a host
composes the wallet and runtime, read the
[wallet library guide](../design-docs/runtime/WALLET_LIBRARY_GUIDE.md). Package
changelogs list every change.

## Type and behavior changes that can break a caller

- **`priorSaid` only.** The IPEX disclosure options (`DisclosureBodyOptions`,
  `GrantPreparationOptions`, and so `prepareOffer`, `prepareGrantBody`,
  `prepareGrantFileBody`, `prepareGrant`, `PresentationOptions` and
  `proposeGroupPresentation`) no longer take the builder's `prior`. Passing it is a type
  error, and untyped input carrying it is refused with a `ValidationError` instead of
  being ignored, which used to send an opening exchange. The `agree` and `spurn`
  presentation input renames `prior` to `priorSaid`. (#1008)
- **Wallet group `present` requires `verb`.** A group's `credentials.present` input is now
  a union keyed by `verb` (`grant`, `offer`, `apply`, `agree`, `spurn`) and the wallet
  proposes the message the verb names. It no longer substitutes a Grant for an Offer or
  refuses the other verbs. (#1011)
- **`unblindingStatus` returns `interrupted` for a discloser that has not begun**, where
  it threw "No Unblind was begun for this Grant". The group wallet's `credentials.unblind`
  used the throw to decide whether to start, so its discloser answer never started; it now
  reads and waits as the group's actual party. (#1014)
- **The live, ended and settled operation tables are private.** The issuance and Unblind
  owners no longer expose `live`, `ended` or `settled`. A raw lookup by Grant compiled but
  was always false, because the keys are `role:grant`. Read operations through `liveOf`,
  `endedOf` and `settledOf`. (#1016)
- **`settleProposedRotation` takes a `ProposedRotation`** (route, event, `smids`, `rmids`)
  instead of a whole `GroupEventResult`. (#1016)
- **Schema validation is a different engine.** `@cfworker/json-schema` replaces Ajv, with
  no code generation. `format` still never rejects, schema documents are still checked
  against their dialect's meta-schema, and an invalid `pattern` still fails when the
  schema is prepared. A schema using `$dynamicRef` is now refused, and so is an unknown
  `$schema`. "Invalid JSON Schema document." carries the reason as its `cause`. (#1013)
- **Unblind after the response, and a new end state.** `requestUnblind` after the verifier
  has answered the presentation throws `PresentationClosedError`, and `UnblindingEndState`
  gains `unneeded`. (#1006, #1014)

## Browser fixes

These three defects were in 2.2.0 and 2.2.1.

- **Errors in a browser bundle.** Constructing any keri-ts error threw a `TypeError`,
  because `AppError` and cesr-ts's `ParserError` set their name from `new.target.name`,
  which the npm build rewrites into a call that needs a polyfill the browser entries never
  load. Every error class now names itself with a string literal. The bundle gate fails
  if a browser entry reaches that call. (#1004; this is the cesr-ts 2.2.1 change.)
- **Held signers at open.** `HaberyArgs.heldSigners` (type `HeldSigners`) is applied with
  `Manager.hold` as the Habery opens, and `openWebWallet` forwards its own `heldSigners`,
  so the first mailbox poll of an identifier whose keys the host keeps is signed.
  Signers are still not stored: pass them at every open. (#1007)
- **Schema validation without `'unsafe-eval'`.** A browser wallet under
  `script-src 'self' 'wasm-unsafe-eval'` can now pin and validate schemas, and take Grant
  and Offer intake. cbor-x comes from its no-eval build, and the bundle gate fails if any
  bundled code contains `new Function(` or a direct `eval(`. (#1013)

## Custodial hosts and two tenants

- **A released signer no longer ends the runtime.** The error is a typed
  `SignerNotHeldError`; the mailbox poller ends such a poll as an `unsignable` outcome and
  waits; every runtime loop restarts after one. `runtime.signerConditions` lists what
  waits, and the wallet's `health()` reports `signer-unavailable`. `Manager.hold()`
  resumes the waiting loops at once. (#995)
- **One ingress URL for several local identifiers.** The handler picks among the
  identifiers sharing the longest matching path by the request's `CESR-DESTINATION`; a
  request with none, or naming none of them, still answers 409. (#995)
- **One Habery on both sides of a Grant.** Issuance operations are keyed by Grant and
  party (`partyKey`, `liveOf`, `endedOf`), and `issuanceStatus`, `waitForIssuance` and
  `abandonIssuance` take an optional `IssuanceParty`. A Habery that holds both parties
  answers for the issuer and says so in `role`. A side is finished when its own exchange
  has retained its root. A recipient held in the same Habery takes the bytes in process.
  (#1000) Unblind is keyed the same way (`unblindingKey`, `UnblindingParty`). (#1006)
- **A non-transferable group member can read its group's mailbox** on a keri-ts host: the
  host verifies the cigar with the key in it and requires that key in the group's current
  key list. (#999)
- **OOBI for an end role (hosting).** A host serves the OOBI of an identifier whose
  accepted, uncut end-role record names one of its local identifiers, so a group's agent
  answers for the group even with an empty `hostedPrefixes`. (#1012)

## Groups

- **Wrapper checks.** A `/multisig` wrapper addressed to an identifier the receiver does
  not hold, or sent by a non-member of a group the receiver is in, is refused before it is
  stored, noticed or listed. A proposal whose event is already in the local KEL lists as
  `inapplicable`. A receipt for the runtime's own group, or for a controller with no end
  role, is no longer attempted. (#996, #1016)
- **Completed events reach every member.** The elected member forwards a completed group
  event to the other signing members (`GroupForwarding`, per-member `GroupDelivery`
  outcomes, retried, never thrown). A member that only receives takes an interaction, a
  registry anchor, a rotation that names the group's current members, or a reply that the
  proposer's signatures already complete, without approving. Consent adds a signature; it
  is not needed to learn a finished event. (#1001)
- **A rotation's proposed members can answer it** before they are signing members, when a
  current member's wrapper for the same rotation names them too. (#1003)
- **Group Apply, Offer, Agree and Spurn** go through `proposeGroupNegotiation`, the same
  consent path as `proposeGroupPresentation` and `proposeGroupAdmit`. (#1011)

## IPEX and Unblind

- **An early Unblind query is held.** A discloser that has not yet received the issuer's
  event anchoring a registry update holds the verifier's query in `heldu`, asks for the
  issuer's KEL through the ordinary query cue, and answers when the event arrives. If it
  never does, the Unblind ends at the Grant deadline with a reason naming the missing
  anchor. (#1014)
- **`unneeded`.** A discloser whose presentation closed before it was asked ends its
  Unblind `unneeded`, which is not a failure. (#1014)
- **Wallet reads.** `credentials.applies` can list answered Applies (`includeAnswered`;
  each entry has `state` and `answer`), `credentials.agreeFor` reads the Agree that
  answers an Offer, and `credentials.pinSchema` keeps schema bytes it was handed.
  `storedExchangeWire` is exported. (#1011, #1016)

## About #1007, #1009 and #1015

#1009 was described as a test fix, but a stale merge resolution in it reverted #1007
(`heldSigners`): its changes to `habbing.ts`, `runtime/index.ts`, `open-web-wallet.ts`,
the guide and its changeset. #1015 restored them. Nothing was lost in the release: at
`v2.2.2` the `heldSigners` code is present in `habbing.ts` and `open-web-wallet.ts`, and
the guide, the runtime export and the wallet test carry it.

## Known limits

- **No durable delivery outbox.** The signed messages an operation still owes its peers
  are held in memory. After a restart an operation that still owed messages reads
  `interrupted`, and the messages are not sent; resend with `resendPresentation` or begin
  again. Work on a durable outbox was started and cancelled; nothing of it is in 2.2.2.
  An issuance that owes nothing but waits on the holder's reply also reads `interrupted`
  after a restart, because the key exchange's ephemeral keys are memory only.
- **Spurn of a Grant that answers an Apply is not allowed.** KERIpy forbids it in both
  its builder and its receiver, and the ACDC specification lists no rejection of a Grant.
  A verifier that does not want such a presentation does not Admit it and keeps the Grant
  and the registry state as evidence. An Admit of a presentation of a revoked credential
  is also refused, on purpose.
- **One registry per DH credential.** A DH registry takes one exchange; a second needs a
  fresh registry.
- The limits listed in the guide's
  [Known limits in 2.2.0](../design-docs/runtime/WALLET_LIBRARY_GUIDE.md#known-limits-in-220)
  still apply, except the three defects of 2.2.0 fixed in 2.2.1 (see its notes).

## Maintainer-only changes

The unit tests run as concurrent shards (#1005, #1010), the Sally interop harness runs in
containers on named volumes (#998), the unit tests stopped re-type-checking the module
graph per process (#1002), and the qualification run's test expectations were updated
(#1018). None changes a published API.
